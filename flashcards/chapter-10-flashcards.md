## Chapter 10: Operating and Monitoring Production Data Workloads — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | BigQuery time travel window: default and maximum configurable value? | Default 7 days, configurable between 2–7 days (max 7). Exam tip: for retention beyond 7 days, use table snapshots instead of relying on time travel. |
| 2 | Cloud Storage Turbo Replication RPO and bucket type requirement? | 15 minutes RPO SLA for 100% of objects; only available on dual-region buckets (not multi-region or regional). Exam tip: this is the go-to answer for 'near-real-time cross-region GCS DR.' |
| 3 | Drain vs Cancel for a Dataflow streaming job — which is data-safe? | Drain: stops new input, finishes in-flight/buffered work, shuts down cleanly (data-safe). Cancel: stops immediately, may lose in-flight data. Exam tip: 'stop without losing data' → drain. |
| 4 | How do you configure a per-task SLA alert in Cloud Composer / Airflow? | Set `sla=timedelta(...)` on the task/DAG and define `sla_miss_callback` to send a notification when the SLA is breached. Exam tip: this is the built-in Airflow mechanism — don't reach for external monitoring for DAG SLAs. |
| 5 | gcloud command to drain a running Dataflow job? | `gcloud dataflow jobs drain JOB_ID --region=REGION`. Exam tip: use this over `cancel` when you need to preserve in-flight streaming data. |
| 6 | Pattern to fix a Dataflow 'hot key' bottleneck (one worker pegged, others idle)? | Salt the key with a random suffix, do a two-stage Combine (partial combine per salted key, then final combine), or use Combine.perKey with fanout. Exam tip: adding workers/machine size does NOT fix hot-key skew. |
| 7 | Pattern for BigQuery cross-region disaster recovery (dataset region is immutable)? | Regularly copy/export-load tables from the source-region dataset into a dataset in the DR region (via BigQuery Data Transfer Service, scheduled queries, or Dataflow). Exam tip: there is no automatic dataset replication feature between regions. |
| 8 | How often can a BigQuery scheduled query be set to repeat, at minimum? | As frequently as every 15 minutes. Exam tip: for sub-15-minute freshness requirements, scheduled queries are the wrong tool — consider streaming/Dataflow instead. |
| 9 | Cloud Monitoring alerting policy: what happens to an open incident if no data arrives? | The incident auto-closes after 7 days of no incoming data. Exam tip: don't assume an alert stays open forever if the metric pipeline itself goes silent. |
| 10 | How do you detect Dataflow 'stragglers' vs 'hot keys' in the console? | The Dataflow job monitoring UI has a 'Stragglers' detection view showing slow-running work items, and separately logs explicit warnings when a hot key is detected in a GroupByKey/Combine step. Exam tip: stragglers = slow individual work items (often due to skew or slow external calls); hot key = one key dominates all traffic. |
| 11 | Command to create a BigQuery table snapshot for backup purposes? | `bq mk --snapshot --expiration=SECONDS project:dataset.snapshot_table project:dataset.source_table`. Exam tip: snapshots persist independently of time travel and can be retained far longer than 7 days. |
| 12 | Cloud SQL: default vs maximum configurable automated backup retention? | Default retention is 7 backups; retention count is configurable up to 365 days of backups, and point-in-time recovery relies on binary log retention (configurable, commonly up to 7 days). Exam tip: PITR requires binary logging to be enabled — it's not on by default with backups alone. |
