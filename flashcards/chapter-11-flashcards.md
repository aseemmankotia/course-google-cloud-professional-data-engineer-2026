## Chapter 11: Security and Compliance for Data Pipelines — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | BigQuery time travel window: default and configurable range? | Default = 7 days. Configurable range = 2 to 7 days (set via MAX_TIME_TRAVEL_HOURS at dataset creation). Exam tip: you cannot go above 7 days. |
| 2 | Cloud DLP FindingLikelihood scale — how many levels, and what are they? | 5 levels: VERY_UNLIKELY, UNLIKELY, POSSIBLE, LIKELY, VERY_LIKELY. Exam tests filtering inspection results by minimum likelihood threshold. |
| 3 | Cloud KMS: minimum automatic key rotation period? | 24 hours (1 day). Exam tip: applies to symmetric CMEK keys used by BigQuery, Cloud Storage, Pub/Sub, Dataflow. |
| 4 | VPC Service Controls vs IAM — core difference? | IAM = identity-based authorization ('can this principal do X'). VPC-SC = perimeter-based context control ('can data cross this boundary'), preventing exfiltration even with valid stolen credentials. They are complementary, not substitutes. |
| 5 | Column-level security vs row-level security in BigQuery — when to use each? | Column-level (policy tags + Dataplex Catalog taxonomy) hides/masks entire sensitive columns (e.g., SSN) for unauthorized users. Row-level (row access policies) filters which rows a user sees (e.g., region = user's territory). Use column for 'hide a field'; row for 'hide some records'. |
| 6 | SQL syntax to create a BigQuery row access policy filtering by the calling user | CREATE ROW ACCESS POLICY my_policy ON project.dataset.table GRANT TO ("group:sales@example.com") FILTER USING (sales_rep_email = SESSION_USER()); |
| 7 | Which IAM role grants access to view masked column values in cleartext under BigQuery column-level security? | roles/datacatalog.categoryFineGrainedReader, granted on the specific policy tag/taxonomy category. Without it, masked values return per the configured masking rule (e.g., NULL, hashed). |
| 8 | Least privilege for a service account that only needs to run BigQuery jobs (no data access)? | Grant roles/bigquery.jobUser only. Contrast with roles/bigquery.user (adds dataset creation) and roles/bigquery.dataViewer (adds read access to data). Exam tests picking the narrowest predefined role, or building a custom role if no predefined role matches exactly. |
| 9 | Which GCP data services support CMEK? | BigQuery, Cloud Storage, Pub/Sub, Dataflow, Dataproc, and more. Exam tip: CMEK controls who can decrypt (via Cloud KMS IAM), not who can query/read the data logically — that's still IAM/row/column security. |
| 10 | Name the Cloud DLP de-identification technique categories tested on the exam | Masking (replace chars), Tokenization/format-preserving encryption (reversible with key), Bucketing/generalization (range instead of exact value), Date shifting (consistent per-entity offset), Redaction (remove entirely). Exam scenario: pick technique based on whether re-identification must be possible. |
| 11 | BigQuery dynamic data masking — what does it enforce and where is it configured? | A masking policy attached to a policy tag returns a transformed value (e.g., ALWAYS_NULL, SHA256 hash, default masking value) to unauthorized queriers instead of the raw column value — configured via Data Policies (Dataplex Catalog) rather than table DDL. |
| 12 | Enforce data residency (e.g., EU-only) at the org level — which control? | Organization policy constraint constraints/gcp.resourceLocations restricted to allowed regions/multi-regions. Prevents resource creation outside approved locations org-wide, regardless of individual user choices. |
