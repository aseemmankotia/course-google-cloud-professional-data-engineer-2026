## Chapter 9: BI, Visualization, and Data Sharing — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | Looker vs Looker Studio — pick one line each for exam use-case selection | Looker Studio: free/lightweight, no modeling layer, best for quick ad-hoc reports & simple dashboards. Looker: enterprise BI platform using LookML semantic layer, Git version control, governed metrics, row-level security, embedding. Exam tip: 'centralized reusable metric definitions across many dashboards' → Looker. |
| 2 | Analytics Hub core objects: Exchange vs Listing vs Linked Dataset | Exchange = container controlling discovery/subscription access (public or private). Listing = reference to one shareable BigQuery dataset published inside an exchange. Linked dataset = read-only dataset in subscriber's project, no data copy/movement. |
| 3 | Analytics Hub billing model — who pays for what? | Data provider pays storage costs only. Subscriber pays compute (bytes scanned) for their own queries against the linked dataset. Exam trap: assuming provider pays subscriber query costs. |
| 4 | LookML core file types | .model.lkml (defines explores/connections), .view.lkml (defines dimensions/measures/tables), .dashboard.lookml (LookML dashboards). All version-controlled in Git for reproducibility. |
| 5 | PDT vs regular derived table in LookML | PDT (Persistent Derived Table): materialized into the database, rebuilt only when its datagroup trigger fires — better performance/cost control. Regular derived table: recomputed at query time every time. |
| 6 | Looker Studio credential modes: Owner's vs Viewer's Credentials | Owner's Credentials: all viewers' queries run/billed under one project (centralized cost, but concentration risk). Viewer's Credentials: each viewer needs their own BigQuery access and is billed individually. Exam tip: cost-governance question about shared dashboards ballooning costs = Owner's Credentials risk. |
| 7 | BI Engine self-service reservation size limit | Reservations can be created from 1 GB up to 100 GB via the Cloud Console self-service UI; larger reservations require contacting your account team. Minimum reservation is 1 GB. |
| 8 | Why does Looker enforce reproducibility better than ad-hoc Looker Studio calculated fields? | Looker's LookML models live in Git with branching, code review, and validation before production deploy, giving one auditable source of truth for business logic. Looker Studio calculated fields are per-report and easily diverge (metric drift). |
| 9 | Row-level security in Looker — mechanism name | User attributes injected into access_filters (or access grants) within the LookML model scope data per user/group without duplicating explores. Central governance + per-user filtering. |
| 10 | Connected Sheets vs Looker Studio — when to choose which | Connected Sheets: spreadsheet-native pivot tables/formulas directly on BigQuery data, no SQL, best for finance/ad-hoc analyst workflows. Looker Studio: purpose-built dashboards/reports for broader audience distribution. |
| 11 | Cost-aware technique: materialized views for BI dashboards | Pre-aggregate common dashboard queries into a BigQuery materialized view; BigQuery automatically serves cached/incremental results, cutting bytes scanned and cost for repeated dashboard refreshes. |
| 12 | BI Engine — what does it accelerate? | In-memory analysis service that accelerates SQL queries from BI tools (Looker Studio, Looker, custom apps) against BigQuery native tables/views, reducing latency and repeated scan cost for interactive dashboards. |
